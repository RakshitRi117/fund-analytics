# Data Dictionary: Bluestock Mutual Fund Analytics

Documents every table in `bluestock_mf.db`: column names, data types, business meaning and source file.

**Conventions**
- Types are SQLite types (`INTEGER`, `REAL`, `TEXT`).
- Money is in Indian rupees. `crore` = 10 million (10,000,000) and `lakh` = 100 thousand (100,000). `lakh crore` = 1,00,000 crore.
- `amfi_code` is the AMFI scheme code, the unique ID of each fund. It links the fund tables together.
- `date_key` is a date written as the number `YYYYMMDD` (for example `20220103`). It links the fact tables to `dim_date`.
- Source files are in `data/raw/`. Cleaned copies are in `data/processed/`.

## dim_fund

One row per mutual fund scheme. Primary key: `amfi_code`.
Source: `01_fund_master.csv`.

| Column | Type | Business meaning |
|---|---|---|
| `amfi_code` | INTEGER (PK) | Unique AMFI scheme code of the fund |
| `fund_house` | TEXT | Asset management company that runs the fund (10 fund houses) |
| `scheme_name` | TEXT | Full name of the scheme, including plan and option |
| `category` | TEXT | Broad fund type: Equity or Debt |
| `sub_category` | TEXT | Specific fund type (for example Large Cap), 12 values |
| `plan` | TEXT | Regular (sold through distributors) or Direct (bought straight from the fund house) |
| `launch_date` | TEXT | Date the scheme started, `YYYY-MM-DD` |
| `benchmark` | TEXT | Market index the fund is compared with (for example NIFTY 100 TRI) |
| `expense_ratio_pct` | REAL | Yearly fee charged by the fund, as a percentage of assets |
| `exit_load_pct` | REAL | Fee charged, as a percentage, when units are sold early |
| `min_sip_amount` | REAL | Smallest allowed monthly SIP instalment (INR) |
| `min_lumpsum_amount` | REAL | Smallest allowed one-time investment (INR) |
| `fund_manager` | TEXT | Person who manages the fund |
| `risk_category` | TEXT | Risk level: Low, Moderate, Moderately High, High or Very High |
| `sebi_category_code` | TEXT | SEBI's code for the scheme category (for example EC01, DC02) |

## dim_date

One row per distinct date found in the datasets. Primary key: `date_key`.
Source: built from the date columns of the other files. Month-level dates (files 04, 05, 06) are stored as the first day of the month.

| Column | Type | Business meaning |
|---|---|---|
| `date_key` | INTEGER (PK) | Date as `YYYYMMDD` |
| `full_date` | TEXT | Date as `YYYY-MM-DD` (unique) |
| `year` | INTEGER | Calendar year |
| `month` | INTEGER | Month number, 1 to 12 |
| `day` | INTEGER | Day of the month |
| `quarter` | INTEGER | Calendar quarter, 1 to 4 |

## fact_nav

Daily NAV (price of one fund unit) for each fund. Primary key: (`amfi_code`, `date_key`).
Source: `02_nav_history.csv`.

| Column | Type | Business meaning |
|---|---|---|
| `amfi_code` | INTEGER (FK) | Fund, links to `dim_fund.amfi_code` |
| `date_key` | INTEGER (FK) | Day, links to `dim_date.date_key` |
| `nav` | REAL | Net Asset Value: price of one unit of the fund on that day (INR) |

## fact_transactions

One row per investor transaction. Primary key: `transaction_id`.
Source: `08_investor_transactions.csv`.

| Column | Type | Business meaning |
|---|---|---|
| `transaction_id` | INTEGER (PK) | Row number generated by the database (not in the source file) |
| `investor_id` | TEXT | Identifier of the investor (5,000 distinct investors) |
| `date_key` | INTEGER (FK) | Transaction date, links to `dim_date` |
| `amfi_code` | INTEGER (FK) | Fund transacted in, links to `dim_fund` |
| `transaction_type` | TEXT | SIP, Lumpsum or Redemption (enforced by a CHECK) |
| `amount_inr` | REAL | Transaction amount in INR (must be above 0) |
| `state` | TEXT | Investor's state (12 states) |
| `city` | TEXT | Investor's city (24 cities) |
| `city_tier` | TEXT | T30 (top 30 cities) or B30 (beyond the top 30) |
| `age_group` | TEXT | Age band: 18-25, 26-35, 36-45, 46-55 or 56+ |
| `gender` | TEXT | Female or Male |
| `annual_income_lakh` | REAL | Investor's yearly income in lakh INR |
| `payment_mode` | TEXT | UPI, Cheque, Mandate or Net Banking |
| `kyc_status` | TEXT | Verified or Pending (enforced by a CHECK) |

## fact_performance

One row per fund with return and risk measures. Primary key: `amfi_code`.
Source: `07_scheme_performance.csv`. The source's `scheme_name`, `fund_house`, `category` and `plan` columns are not copied here, because they are in `dim_fund`.

| Column | Type | Business meaning |
|---|---|---|
| `amfi_code` | INTEGER (PK, FK) | Fund, links to `dim_fund` |
| `return_1yr_pct` | REAL | Return over the last 1 year, in % |
| `return_3yr_pct` | REAL | Annualised return over 3 years, in % |
| `return_5yr_pct` | REAL | Annualised return over 5 years, in % |
| `benchmark_3yr_pct` | REAL | Benchmark's 3-year return, in %, for comparison |
| `alpha` | REAL | Return earned above what the fund's risk level would predict |
| `beta` | REAL | Sensitivity to the market: 1 moves with it, above 1 moves more |
| `sharpe_ratio` | REAL | Return earned per unit of total risk |
| `sortino_ratio` | REAL | Like Sharpe, but counts only downside risk |
| `std_dev_ann_pct` | REAL | Yearly standard deviation of returns, in % (volatility) |
| `max_drawdown_pct` | REAL | Largest fall from a peak to a low, in % (negative) |
| `aum_crore` | REAL | Assets under management of the scheme, in crore INR |
| `expense_ratio_pct` | REAL | Yearly fee, in % |
| `morningstar_rating` | INTEGER | Morningstar star rating |
| `risk_grade` | TEXT | Risk level label |

## Cleaning notes

- **Dates:** all date columns were stored as text in the raw files and were converted to real dates during cleaning.
- **`fact_nav` row count:** the source has 46,000 rows (trading days only). After forward-filling weekends and holidays with the last known NAV, each of the 40 funds has 1,608 calendar days, giving 64,320 rows.
- **Duplicates:** none found in any file.
- **Invalid values:** no NAV at or below 0, no transaction amount at or below 0, and `transaction_type` and `kyc_status` already held only valid values.
- **Expected nulls:** `yoy_growth_pct` is empty for the first 12 months because there is no earlier year to compare with. These were left as they are.
- **Different date ranges:** NAV and benchmark data start in 2022, transactions in 2024 and category inflows in April 2024, so compare tables only over the period they share.
- **Folio data:** `06_industry_folio_count` is reported quarterly even though its date column is named `month`.
